# Heading

A section's heading, on the `<h1>`–`<h6>` the platform already has. It exists to
separate two things raw markup forces into one decision: **what a heading is**
(`level`, the tag and the outline) and **how big it looks** (`size`, the heading it
resembles).

## Usage

Pass `level` and nothing else almost always — each level already renders at the
size that belongs to it.

<Canvas of={HeadingStories.Levels} />

### Size is not level

When the design asks for a smaller heading, the answer is a smaller `size`, not
a deeper `level` — and `size` is named for the heading it resembles, so
`level={2} size="h4"` reads as the sentence itself: an h2 that looks like an h4.
These three are all `<h2>`: the outline reads h2, h2, h2, and only the type
changes. Without the split, the quiet one becomes an `<h4>` and
every screen reader user inherits an outline that describes the design instead
of the page.

## Accessibility

- **The element is the semantics.** `level` renders a real `<h1>`–`<h6>`, so the
  heading appears in the rotor, in the outline, and under "next heading"
  navigation with no ARIA at all.
- **`level` is required and never guessed.** A default would be invented from
  nowhere — the component cannot see where it sits — and a wrong heading level
  fails silently for everyone who does not use a screen reader.
- **Do not skip levels to get a size.** Skipping breaks the outline (WCAG 1.3.1;
  the relevant technique is G141, hierarchical organisation — H42 is only about
  using `h1`–`h6` at all); `size` is there precisely so you never have to.
- **The name is its text**, so it needs no `aria-label`; one would replace the
  visible text for screen reader users while sighted users read something else.
  (Not WCAG 2.5.3 — that one is scoped to interactive components.) `role` and
  `aria-level` are refused by the type: measured, both reached the DOM and
  overruled `level` with no warning.
- **Two-line headings are balanced**, where the browser supports it: the second
  line no longer carries a single orphan word. It is `text-wrap: balance`,
  applied always rather than offered as a prop — nobody asks for the unbalanced
  version. Where it is missing the heading wraps normally.
- **The ladder is strictly decreasing and stops at body size.** `h6` renders at
  the body step and no smaller: a heading smaller than the text around it is one
  a sighted reader cannot find. Every step is pinned by a test, because a
  level→size map that had `h4` larger than `h1` once passed the whole suite.
