# Heading

A section's heading, on the `<h1>`–`<h6>` the platform already has. It exists to
separate two things raw markup forces into one decision: **what a heading is**
(`level`, the tag and the outline) and **how big it looks** (`size`, a step of
the type scale).

## Usage

Pass `level` and nothing else almost always — each level already renders at the
size that belongs to it.

<Canvas of={HeadingStories.Levels} />

### Size is not level

When the design asks for a smaller heading, the answer is a smaller `size`, not
a deeper `level`. These three are all `<h2>`: the outline reads h2, h2, h2, and
only the type changes. Without the split, the quiet one becomes an `<h4>` and
every screen reader user inherits an outline that describes the design instead
of the page.

## Accessibility

- **The element is the semantics.** `level` renders a real `<h1>`–`<h6>`, so the
  heading appears in the rotor, in the outline, and under "next heading"
  navigation with no ARIA at all.
- **`level` is required and never guessed.** A default would be invented from
  nowhere — the component cannot see where it sits — and a wrong heading level
  fails silently for everyone who does not use a screen reader.
- **Do not skip levels to get a size.** Skipping breaks the outline (WCAG 1.3.1,
  and the H42 technique); `size` is there precisely so you never have to.
- **The name is its text**, so it needs no `aria-label` — and one would override
  the visible text, which WCAG 2.5.3 asks you not to do.
- Below `h4` the default stops shrinking at body size: a heading smaller than
  the text around it is one a sighted reader cannot find.
