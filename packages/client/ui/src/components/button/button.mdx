# Button

Lets the user trigger an action — submit, confirm, delete — or, with the `as` prop, navigate with
the look of a button. Built on the native `<button>`: accessible and themable out of the box.

## Props

Defaults: `variant="primary"`, `size="md"`, `type="button"` (on the native element).

<Controls of={ButtonStories.Primary} />

## Usage

### Variants

The colour role is the `variant` axis — each maps 1:1 to a token action family, so every variant
has real hover/active/disabled colours in both themes (try the **Theme** toolbar).

<Canvas of={ButtonStories.Gallery} />

### Sizes

`size` is orthogonal to the colour role. Heights are **explicit** — `sm` 32px, `md` 36px, `lg`
44px — so buttons align deterministically and don't drift with the font tokens. `lg` meets the
44px (AAA) touch target; `sm` clears the WCAG 2.5.8 minimum (24px) but is meant for dense,
pointer-first surfaces — prefer `md`/`lg` where touch is primary.

<Canvas of={ButtonStories.Sizes} />

### With an icon

The `icon` slot is decorative (`aria-hidden`) next to a visible label. While loading, the spinner
takes the icon's slot **in place**, so an icon-bearing button never changes width; a button with no
icon grows by the spinner's width when loading starts — give it an icon (or a fixed width) if that
shift matters.

<Canvas of={ButtonStories.WithIcon} />

A **trailing** icon (`iconEnd` — chevron, external link…) stays visible while loading, since the
leading spinner carries the state:

<Canvas of={ButtonStories.WithIconEnd} />

**Icon-only** buttons are **square** (width = the size's height) and have no discernible text, so
`aria-label` is **required** — a dev warning fires without it:

<Canvas of={ButtonStories.IconOnly} />

### Disabled

Native `disabled` — the platform blocks focus and activation; each variant uses its family's
disabled colours (no opacity hack).

<Canvas of={ButtonStories.Disabled} />

### Loading

`isLoading` is **pending, not disabled**: activation is blocked (`aria-disabled` + a click guard,
on every polymorph) but the button **keeps focus** — a mid-click `disabled` would drop focus to the
page — and keeps its variant colours; only the spinner signals the wait. Screen-reader users are
told the action is in progress: `aria-busy` plus a **persistent, visually-hidden `role="status"`
region rendered outside the button** in the user's language — outside, so the status never joins
the button's accessible name; persistent, so the start of loading mutates an existing region (the
reliable announcement path). The end is conveyed by `aria-busy` clearing and the region emptying.
The design system owns this copy, since it never asks the app for strings.

<Canvas of={ButtonStories.Loading} />

**Double submissions.** `isLoading` is controlled, so a second physical click can land before your
state update re-renders. Either set it synchronously — or simply **return a Promise from
`onClick`**: the button then manages its own pending state (spinner, `aria-disabled`, announcement)
until it settles, and a synchronous internal guard closes the double-click race.

### As a link (`as`)

Render as any element or component while keeping the button's look: `as="a"` (or `as={Link}`). The
props of the `as` element are typed (`href` is allowed here, not on a plain button); button-only
attributes (`type`, `disabled`) are not applied to non-`<button>` elements.

## Accessibility

- **Icon-only** buttons need an `aria-label` — a dev warning fires if it is missing (see the
  icon-only story above).
- The **loading** state is pending, not disabled: the button stays focusable (`aria-disabled` +
  click guard, never native `disabled` — which would drop focus mid-interaction) and the status is
  exposed to assistive tech (`aria-busy` + a persistent, visually-hidden localized `role="status"`
  region outside the button — the name stays clean and the start announcement is reliable); the
  spinner is decorative (`aria-hidden`) and respects
  `prefers-reduced-motion`.
- **Direction** follows the active locale (RTL/LTR). Styling uses CSS logical properties, so the
  layout mirrors automatically — try the Locale toolbar (`العربية`).
- Contrast of every variant is enforced twice: at token level (WCAG AA pairs per theme) and on the
  rendered component (axe, light and dark).
