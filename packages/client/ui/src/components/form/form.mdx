# Form

The `<form>` element, and the adapter scope for everything inside it.

Give the form binding **once**, where the design system is set up:

```tsx
<UiProvider adapters={{ i18n, form: { field: useRhfField, status: useRhfStatus } }}>
```

and from then on a form is just a form:

```tsx
<Form onSubmit={form.handleSubmit(save)}>
  <FormInput name="email" label="Email" />
  <FormSubmit>Create account</FormSubmit>
</Form>
```

It renders **one** element. The adapter scope is context, which costs no markup.

## Why this is a component and not a bare `<form>`

For one attribute, and the argument is the whole reason. With the browser's own validation left on, a
`required` field **blocks submission before your handler ever runs** — measured, the handler is
called **zero** times — and the browser shows its own bubble, unstyleable and in its own language,
next to the `FieldError` you rendered.

Forgetting `noValidate` is silent and fatal, so it lives where it cannot be forgotten. A test pins
the trap on a bare `<form>` too, so the reason cannot rot.

## What it does not do

**It does not own submission.** `onSubmit` is yours, and with a form library it is that library's
handler. The design system holds no form state (ADR-0013) — it renders what your library decides.

Native form props pass through, React 19 `action` included; with an action, `FormSubmit` reads
`useFormStatus` from React itself and needs no adapter at all.

## Accessibility

- **One `<form>`, no wrapper**, so landmarks and the accessibility tree see exactly what you wrote.
- The bound components inside keep their own guarantees: label association by id, messages announced
  through `aria-describedby`, `aria-invalid` following the message.
- Pair it with `FormErrorSummary` on any form long enough that a failure could scroll out of view.
