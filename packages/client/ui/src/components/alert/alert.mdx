# Alert

A prominent inline message that gives the user feedback — success, a warning, an error, or
information. Built on a `<div>`; the `variant` carries the meaning through colour **and** a
visually-hidden severity word, so the status reaches assistive tech, not just the eye.

## Props

Defaults: `variant="info"`; `live` defaults by variant (`error` is assertive, the rest polite).

<Controls of={AlertStories.Default} />

## Usage

### Variants

`variant` is the semantic status role — `info` · `success` · `warning` · `error`. Each is the
tinted-surface treatment of its token family (`*-subtle` fill, `*-subtle-foreground` text,
`*-border`), so every one has real colours in both themes (try the **Theme** toolbar). `error` is
the feedback-red status family, distinct from the `destructive` action role used by buttons.

## Accessibility

- **Status is never colour alone** (WCAG 1.4.1). A visually-hidden, localized severity word
  (“Error:”, “Warning:”…) is announced before the message, so a screen-reader user gets the status a
  sighted user reads from the colour and icon.
- **Announcement politeness is calibrated.** `live` maps to the ARIA live region: `assertive` →
  `role="alert"` (interrupts — the default for `error`), `polite` → `role="status"` (waits for a
  pause — the default for the rest), `off` → no live region. Use `off` for an alert already on the
  page at load; the derived role is authoritative (a stray `role` in spread props can't clobber it).
- **Announcement is not guaranteed by `live` alone.** A live region inserted already containing its
  text is announced unreliably by screen readers — especially `polite`. For dynamic feedback that
  must be heard, **keep the Alert mounted and change its content** (mutating an existing region is
  the reliable path); for one-shot transient messages, a dedicated live-region/toast fits better
  than an inline Alert. `error`/`assertive` is the most tolerant of insert-with-content.
- **`title` is a content slot**, not the native tooltip attribute — it renders as the bold lead-in.
- **Not interactive.** A dismiss button or action is a separate concern (a real `<button>` with its
  own label) — compose it, or a future dismissible variant will add it.
- **Forced colors:** the tint collapses to a system surface, so the always-present border keeps the
  alert bounded and the severity word keeps the meaning.
