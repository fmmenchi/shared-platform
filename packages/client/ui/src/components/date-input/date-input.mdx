# DateInput

One text field that shows a date **the way your locale writes it** and stores it
as ISO. It is the design system's date field.

It is **not** a wrapper around `<input type="date">`. That control is refused by
`Input` (ADR-0027) for the one reason this component exists: its segment order
comes from the browser, so on a page whose language your app declares it
disagrees with the `Time`, the `Numeric` and the formatted `Table` cell beside
it — silently, with no test going red.

## Usage

### The same date, four locales

<Canvas of={Stories.AcrossLocales} />

One ISO value — `2026-08-12` — under four locales. The **order** moves, the
**separator** moves, and what is stored never does. Both come from
`Intl.DateTimeFormat(locale).formatToParts()` with the locale `UiProvider` was
given: the same one `useFormatter()` hands `Time` and `Numeric`, which is what
keeps a page agreeing with itself. The separator is read from that pattern
rather than chosen, so `de` gets `12.08.2026` without a line of code about it.

**To re-locale one part of a page**, nest a `UiProvider`. There is deliberately
no `locale` prop: it would let this field say `it` while the `Time` beside it
says `en`, and it could not carry direction — a nested provider re-derives `dir`,
so an Arabic subtree lays out right-to-left.

### The format hint

<Canvas of={Stories.TheFormatHint} />

The placeholder is assembled, not written down: the **letters** are design-system
copy (`gg` in Italian, `dd` in English) and the **frame** is the locale's own
pattern. Neither `gg/mm/aaaa` nor `mm/dd/yyyy` appears as a string anywhere,
which is what makes the twenty-seventh locale an addition rather than a rewrite.

### What it stores

<Canvas of={Stories.ReadingTheValue} />

Three things, kept apart on purpose:

- **In the DOM**, one ISO `YYYY-MM-DD` string, under one `name`. A server never
  receives `12/08/2026` and has to guess which number is the month.
- **To you**, a `CivilDate`: `{ year, month, day }`, months **1–12** as a human
  and ISO 8601 write them, through `onDateChange`.
- **Never a `Date`.** A `Date` is an instant; a birthday has no timezone.
  `new Date('2026-08-12')` is the 11th of August in every zone west of
  Greenwich, and so is the browser's own `valueAsDate`.

**Typing is forgiving; the order is not.** `12/08/2026`, `12-08-2026`,
`12.08.2026` and `12 08 2026` are all read — a person uses whatever their
keyboard puts under their thumb. What is not negotiable is which number is the
day, because `03/04` means nothing without it.

Three things hold nothing rather than guessing: a half-typed date, a date that
does not exist (30 February stays empty instead of sliding to 2 March the way
`new Date` does), and a **two-digit year** — `26` is the year 26 or it is
nothing, because guessing a century is a guess that fails silently.

### In a form

<Canvas of={Stories.InAForm} />

The value lives on a carrier: a text input hidden beside the field. It is hidden
with the **`hidden` attribute** and not `type="hidden"`, and that is the whole
design — measured, `form.reset()` restores the first and not the second, so a
`type="hidden"` carrier would come back from a reset holding a stale value while
the field beside it went back. React also declines to wire `onChange` on
`type="hidden"`, so a `register()`-style binding would hear nothing.

`required` marks the visible field, never the carrier: a required carrier would
be an invalid control the browser cannot focus, and a browser asked to report on
one refuses the submit while showing the user nothing. `disabled` marks both,
because a disabled control is not submitted and a carrier left enabled would
keep posting for a field the user was told they cannot touch.

## Accessibility

- **Give it a label**, exactly as you would `Input`: a `Field`, a wrapping
  `<label>`, or `aria-label`. This is one text field, so a `<label for>` names
  it — there is no group here and no legend.
- **The placeholder is a format hint, not a name.** It disappears on input, so
  the field still needs a label of its own.
- **`inputMode="numeric"`, not `type="number"`**: the numeric keypad on touch
  without the spinners, the `1e4`, or the empty-when-invalid value that would
  hide a defect rather than show it.
- **`ref` reaches the visible input**, so an error summary can focus the field.
- **`autoComplete="bday"`** is set, so a browser can fill a date of birth the
  way it fills an address. Override it for any other kind of date.
