# Field

Groups a label, a control, and optional description/error text, and wires them for accessibility so
you don't hand-thread ids. Compose it: `<Field><FieldLabel/><Input/><FieldDescription/><FieldError/></Field>`.
It shares one id between the label's `htmlFor` and the control, registers the description and error
into the control's `aria-describedby`, and drives its `aria-invalid` from `invalid` — via React
context, so any transparent control inside picks the wiring up (the control's own props still win).
It owns no value or validation (ADR-0013) and has no chrome of its own — just layout and the text roles.

## Anatomy

- **`Field`** — the group; takes `invalid` and provides the context.
- **`FieldLabel`** — `<label>` tied to the control (click-to-focus, name-from-label).
- **`FieldDescription`** — helper text, added to `aria-describedby`.
- **`FieldError`** — the message; renders and joins `aria-describedby` **only when it has content**.

## Accessibility

- **Label association is automatic** — `FieldLabel htmlFor` and the control's `id` share one `useId`,
  so clicking the label focuses the control and the control's name comes from the label.
- **Description & error are announced with the field** — both register into `aria-describedby`; the
  error only when it has content, so no empty/dangling references.
- **Invalid isn't colour alone** — `invalid` sets `aria-invalid` (announced) and the control shows a
  colour **and** a thicker border; the error text adds the words.
- **Announcing a fresh error is the consumer's job** — `FieldError` is described-by, not a live
  region. For an error that must be heard on submit, move focus to the field or use an error summary.
- **Escape hatch:** a control's own `id` / `aria-describedby` / `aria-invalid` override the field's.
