# ChoiceField

A single choice and the words next to it — a consent checkbox, a lone radio. The control leads, its label sits beside it, and the hint and error line up under the **label** so the text reads as one block.

```tsx
<ChoiceField label="Accept the terms" error={errors.tos?.message}>
  <Checkbox {...adapter('tos')} />
</ChoiceField>
```

## When to use it — and when not to

**It earns its place only when there is something to say.** With no hint and no error, a plain nested label is smaller markup and does the same job:

```tsx
<label>
  <Checkbox /> Accept the terms
</label>
```

What `ChoiceField` adds is the wiring a bare label cannot do: a shared `id`, `aria-describedby` pointing at the hint and the error, and `aria-invalid` on the control. Reach for it when the choice can fail validation or needs explaining; otherwise the label is the better answer (ADR-0016).

For **several related choices** the field is the group, not the option — use a `Fieldset` with a `FieldsetLegend` and give each option its own `<label>`. See [Fieldset](?path=/docs/components-inputs-fieldset--docs).

## Why it is not a prop on `Field`

`Field` puts the label above the control; this puts the control first. They are two anatomies, and they take different props — here the label is **required** and the hint is rare, there the label is optional because you may compose it and the hint is common. One component covering both would carry props that apply to only half its uses, and every call site would have to say which half it meant.

The wiring is shared, not duplicated: both containers use the same internal hook for the id, the description registry and the dev guards. Only the anatomy differs.

## Accessibility

- **The control comes first in the DOM as well as on screen**, so reading order matches visual order (WCAG 1.3.2) instead of being reordered by the grid.
- **The label is required**, and clicking it toggles the control — it is a real `<label>` bound by `htmlFor`.
- **The hint and the error are announced with the control**, in DOM order, through `aria-describedby`. Each renders only when it has content, so the control never points at a blank element.
- **`invalid` follows the error** unless you set it, so the announced state and the visible message cannot disagree.
- **One control per field.** Two share one id, which is flagged in development. A group belongs in a `Fieldset`.
