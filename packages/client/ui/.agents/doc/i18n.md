# i18n (agent)

- Copy is **colocated + typed**: `<name>.messages.ts` → `defineMessages('<ns>', { en/it/ar })`
  (type requires every locale + same keys). Read via `useMessages(catalog)` — typed `t`, base-locale
  fallback outside a provider.
- App overrides a label via the `messages` port, key `"<ns>.<key>"`. No central catalog, no i18n
  engine.
- **A message with a moving part is ONE string with a hole in it** — `back: 'Back to {name}'`, read
  as `t('back', { name })` — never a fragment the component finishes with `+`. Concatenating puts the
  WORD ORDER in the code: every locale is then forced into "«something» «name»", which Japanese is
  not (共有に戻る — the name first, the verb last) and which Turkish and Finnish inflect. It is not
  only translators this shuts out: an app overriding `"<ns>.<key>"` can replace the fragment and not
  the order, so the seam we ship is unusable for exactly the languages that need it. An unfilled hole
  is left VISIBLE (`{name}`) and warned about in dev — a bug that gets reported beats a label that
  quietly says less than it should.
- `direction` derived from `Intl.Locale.maximize().script` (Baseline), never injected; use CSS
  logical properties.
